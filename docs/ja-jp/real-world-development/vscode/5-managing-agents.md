GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、自分のマシン上でリアルタイムに実行される作業を確認できます。ツールの呼び出しやファイルの編集が進むたびに表示されるため、差分をインラインでレビューし、個々の変更を承認または拒否し、エディターを離れずに追加のプロンプトで会話を方向付けられます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムに監視します。
- 提案されたファイル編集をレビューして承認します。
- 作業中のセッションに追加の指示を送り、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントは、ハイ コントラスト モードを実装しています。作業の途中で、デザイン チームから追加の要望がありました。既定のテーマが暗すぎると感じる利用者向けに、ライト モードの切り替えも追加したいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各作業が表示されます。調査するファイル、実行するコマンド、提案する編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールして各ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると、変更を承認します。
   - **Undo** を選択すると、変更を元に戻し、エージェントに再度対応させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** の確認を表示します。内容を確認し、問題ないコマンドだけ許可してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。完了すると、変更をまとめたメッセージが表示されます。

## エージェントにライト モードの追加を依頼する

ハイ コントラスト モードができたので、同じ会話を続けてライト モードの切り替えを追加します。同じチャット セッションを使うため、エージェントは以前の作業で変更したコンポーネント、スタイルの方法、local storage のパターンを把握しています。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を調べ、ライト モードの追加を提案します。
3. 新しい編集を確認し、ハイ コントラスト モードと同様に、各差分で **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば、切り替え UI を好みと異なる方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を加えた追加プロンプトを送信します。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すよりも効率的です。追加のプロンプトで、調整 (「CSS を簡潔にし、セレクターを重複させず CSS 変数を使う」)、軌道修正 (「3 つ目の切り替えを追加せず、ライト モードを既存の設定パネルに追加する」)、範囲の拡張 (「両方の切り替えにキーボード ショートカットも追加する」) ができます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開いて差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage への保存など、カスタム エージェントが示したアクセシビリティのパターンが反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、作業中のセッションを監視して方向付けました。ファイル編集をレビューし、変更を承認または拒否し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムに監視する
- 個々のファイル編集を承認または拒否する
- 追加プロンプトで作業中のセッションを方向付ける
