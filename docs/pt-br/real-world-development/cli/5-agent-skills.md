Escrever código é apenas parte do trabalho. Você já confirmou manualmente que o código funciona e usou arquivos de instruções para garantir que ele siga os padrões do projeto. E os testes, o lint e as outras partes da integração contínua (CI)?

Para esse tipo de tarefa, as **skills de agente** são ideais. Elas ajudam o Copilot a entender como executar operações como essas.

Nesta lição, você vai:

- explorar a skill `quality-checks` existente.
- personalizar o formato dos resultados.
- recarregar e executar a skill.

## Cenário

O Tailspin Toys usa a skill `quality-checks` para testes de unidade, lint e verificações de tipos. A equipe quer melhorar o relatório para facilitar a leitura dos resultados.

## Instruções, scripts e recursos

As skills de agente reúnem instruções reutilizáveis para tarefas, scripts executáveis e recursos de apoio que o agente carrega quando necessário. Em geral, uma skill é uma pasta com o nome da skill e um arquivo Markdown `SKILL.md`. Esse arquivo contém frontmatter com nome e descrição, uma visão geral do que a skill faz e orientações sobre quando usá-la. A pasta também pode conter subpastas com scripts e outros recursos.

> [!NOTE]
> Uma skill não precisa de arquivos e pastas adicionais. A skill `quality-checks` do Tailspin Toys contém somente `SKILL.md` porque usa os comandos já existentes no projeto.

As skills podem ficar na pasta `.github/skills` do projeto, como um recurso do repositório que a equipe compartilha e reutiliza, ou na pasta pessoal de skills `~/.copilot/skills`.

## Explore a skill

Explore a skill que a equipe do Tailspin Toys criou para executar testes de unidade, lint e verificações de tipos, chamada `quality-checks`.

1. Volte ao seu Codespace. No editor do Codespaces, abra `.github/skills/quality-checks/SKILL.md`.
2. Leia os campos `name` e `description` no início. A descrição ajuda o Copilot a entender quando chamar a skill.
3. Leia as instruções e observe como elas orientam o Copilot durante os testes e o lint.
4. Observe que a skill ainda não tem uma seção **Results output formatting**.

## Execute a skill antes de fazer alterações

As skills podem ser chamadas diretamente pelo Copilot CLI ou por uma solicitação em linguagem natural. Peça ao Copilot para executar as três verificações da skill.

1. Volte à conversa de filtragem no modo Interactive.
2. Use este prompt:

   ```plaintext
   Run the quality-checks skill for unit tests, lint, and type checks.
   ```

3. Observe o relatório final.

## Personalize o relatório

Melhore o relatório para que ele informe o que foi executado, se houve sucesso e o que as ferramentas relataram. Atualize a skill para produzir esse relatório.

1. Volte para `.github/skills/quality-checks/SKILL.md`.
2. Adicione a seguinte seção ao final do arquivo:

   ```markdown
   ## Results output formatting

   Upon completion, report each command that ran and whether it passed, failed, or was blocked. Include test counts, durations, errors, warnings, and other metrics only when the tool reports them. Identify the next action for any failure or blocker, and never describe a skipped or incomplete check as passed.
   ```

3. O arquivo é salvo automaticamente.

## Execute a skill atualizada

Agora, veja a skill em ação. O Copilot CLI pode recarregar skills editadas sem reiniciar a conversa.

1. Digite:

   ```plaintext
   /skills reload
   ```

2. Use exatamente o mesmo prompt de antes:

   ```plaintext
   Run the quality-checks skill for unit tests, lint, and type checks.
   ```

3. Observe o relatório final e compare-o com o primeiro.
